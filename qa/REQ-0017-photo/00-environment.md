# 00 — Окружение, запуск, ввод, верификация

> Общая преамбула для всех тест-кейсов REQ-0017-photo. Прочитай перед первым прогоном.

## Системные предусловия

- ОС Linux/X11 (игра использует захват мыши; на Wayland инжекция ввода идёт через `ydotool`).
- Сборка C#: `dotnet build` (обязательно после любого изменения `.cs`).
- Ассеты импортированы: `"$GODOT" --headless --import`.
- `DISPLAY=:0` доступен (GUI-окно). Без GUI визуальные тесты (F-34) невыполнимы.

### Путь к движку (абсолютный, из репозитория)

```bash
GODOT="$PWD/.bin/Godot_v4.7-stable_mono_linux_x86_64/Godot_v4.7-stable_mono_linux.x86_64"
```

## Стартовая конфигурация игры (важно для setup'ов)

- **Старинный фотоаппарат засевается в слот 0** (`InventoryHud._Ready`): ряд 1, колонка 1 → активация `I` → `1` → `1`. Тип `vintage_camera`, паттерн B.
- **Теннисный мячик засевается в слот 1**: ряд 1, колонка 2.
- **Фотография НЕ засевается** — создаётся только успешным использованием камеры.
- Лог старта: `[Inventory] Seeded 2/12 items`.
- Игрок стартует в клетке входа (`PlayerStartCell`), смотрит в коридор. Мышь захвачена всегда.
- **При каждом прогоне необходимо создавать фотографию заново** через камеру: активация фотоаппарата → ЛКМ → ожидание отсчёта → фотография в слоте 0.

### Создание фотографии (базовый setup для всех тестов)

```
I → 1 → 1 → I (активировать камеру в слот 0)
→ ЛКМ (открыть видоискатель, начать отсчёт)
→ подождать ~2 с (3 тика по ~0.67 с) — завершение отсчёта
→ фотография создана в слоте 0, слот бронирован
```

> **Важно:** перед ЛКМ камера игрока должна смотреть в открытое пространство на ≥ 1.8 юнита (фокусное расстояние видоискателя). Если камера направлена в стену, видоискатель сразу отменяется: `[Camera] Focus blocked — too close`. Используй `mouse_motion dx:0 dy:-20` перед ЛКМ, чтобы гарантировать взгляд вдоль пола/коридора, а не в стену.

### Пространственные ограничения (важно для setup'а)

| Параметр | Значение | Влияние на тесты |
|----------|----------|------------------|
| `FocusMinDistance` (камера) | 1.8 юнита | Перед ЛКМ игрок должен быть ≥ 1.8u от стены по лучу взгляда |
| `EnterDuration` (фото) | 1.3333 с | Нужен коридор ≥ ~10u для непрерывного хода вперёд |
| Порог продвижения | `Speed * 0.4` | Скорость игрока должна набраться, чтобы прогресс начал копиться |
| `FlashDuration` | 0.6 с | Длительность жёлтого мерцания после телепорта |
| `TickSeconds` (видоискатель) | 0.6667 с | Каждый тик отсчёта 3→2→1: полный отсчёт ~2.0 с |

### Позиционирование для setup'ов

**Success-path (нужно свободное пространство впереди):**
```json
{ "type": "mouse_motion", "dx": 0, "dy": -20, "reason": "опустить камеру — смотреть вдоль пола, не в стену" },
{ "type": "wait_frames", "frames": 5 }
```

**Failure/wall-path (нужна стена впереди):**
```json
{ "type": "aim_camera", "yaw_deg": 180.0, "reason": "разворот на 180° — смотреть в стену позади старта" },
{ "type": "wait_frames", "frames": 10 }
```

## Запуск тестовой сессии

Игру нужно запустить с захватом stdout в лог (все верификации по консольным маркерам):

```bash
# 1. Сборка
dotnet build

# 2. (если нужен свежий импорт) "$GODOT" --headless --import

# 3. Запуск окна с логом
DISPLAY=:0 "$GODOT" --path . > /tmp/photo_test.log 2>&1 &
GODOT_PID=$!

# дать окну раскрыться
sleep 6

# 4. Активировать окно Godot для инжекции клавиш
xdotool search --sync --name "Maze" windowactivate %@
```

По окончании сессии: `kill $GODOT_PID`. Лог живёт в `/tmp/photo_test.log`.

## Инжекция ввода

Мышь в игре захвачена (`MouseMode = Captured`). Используй `xdotool` (X11).

| Действие в игре | Команда xdotool |
|-----------------|-----------------|
| Открыть/закрыть инвентарь (I) | `xdotool key i` |
| Выбрать ряд 1 / колонку 1 (слот 0) | `xdotool key 1` ; `xdotool key 1` |
| Выбрать ряд 1 / колонку 2 (слот 1) | `xdotool key 1` ; `xdotool key 2` |
| Движение (W/A/S/D) | `xdotool keydown w` … `xdotool keyup w` |
| Обзор мышью (yaw/pitch) | `xdotool mousemove -- 50 0` (относительные) |
| ЛКМ (Левый клик) | `xdotool click 1` |
| Выход | `xdotool key ctrl+q` (или `kill $GODOT_PID`) |

**Тайминги:**
- Отсчёт видоискателя: ~2.0 с (3 тика × TickSeconds=0.6667). Ждать: `sleep 2.5`.
- Вход в фото: `EnterDuration = 1.3333 с`. Учитывай разгон скорости (~0.3 с). Ход вперёд: `xdotool keydown w && sleep 2.5 && xdotool keyup w`.

> Если `xdotool key` не доходит — проверь фокус окна (`xdotool getactivewindow`).

## Способы верификации

### 1. Консольные маркеры (основной способ для логики)

Игра пишет в stdout узнаваемые строки. Проверяй через `grep` по `/tmp/photo_test.log`:

| Маркер | Что означает |
|--------|--------------|
| `[Inventory] Seeded 2/12 items` | Камера и мяч засеяны (слоты 0, 1) |
| `[Camera] Viewfinder open, countdown start` | Видоискатель открыт, отсчёт 3→2→1 начался |
| `[Camera] Focus blocked — too close` | Фокусный луч упёрся в стену — отсчёт отменён |
| `[Camera] Focus lost during countdown — reset` | Игрок отвернулся во время отсчёта — сброс |
| `[Camera] Shutter — photo created` | Отсчёт завершён, сработал затвор (колбэк OnCameraFired) |
| `[Camera] Photo created at (x, z) yaw=N → slot 0` | Фотография создана с координатами, положена в слот |
| `[Inventory] Activate 'photo' → hand (slot 0 reserved)` | Фотография активирована в руку, слот 0 забронирован |
| `[Inventory] Deactivate 'photo' → slot 0` | Фотография деактивирована (вернулась в слот 0) |
| `[Inventory] Drop 'photo' → world at (x, z)` | Фотография выброшена в мир |
| `[Inventory] Pickup 'photo' → slot N` | Фотография подобрана обратно в инвентарь |
| `[Photo] Entered → teleported` | Вход завершён, сработал телепорт |
| `[Player] Teleport → world=(x, z) yaw=N pitch=N` | Игрок телепортирован в запечатлённую точку |

Пример проверки:

```bash
grep -E "\[Camera\]|\[Photo\]|\[Player\] Teleport" /tmp/photo_test.log | tail -20
```

### 2. Скриншоты (визуал / модель)

