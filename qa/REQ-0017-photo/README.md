# QA — REQ-0017-photo (Фотография)

> **Фича:** [REQ-0017-photo](../../requirements/REQ-0017-photo/README.md) · **User Story:** US-17
> **Покрытие:** F-31, F-32, F-33, F-34 + визуальное представление + регрессии
> **Тип документа:** ручные/полуавтоматические тест-кейсы (WHAT + инструкция по исполнению)
> **Исполнитель:** автономный QA-агент (или человек). Требует GUI-окна Godot и инжекции ввода.

Набор тест-кейсов, покрывающих фотографию как игровой предмет-портал: жизненный цикл
(создание из камеры, активация/деактивация, drop/pickup, одноразовое уничтожение при входе),
неизменяемость запечатлённых данных, механику входа движением вперёд (накопление/сброс
прогресса, условие реального продвижения, телепорт) и визуальное сопровождение (живое окно
вида, рост с прогрессом, «оживание» освещением, жёлтое мерцание при переносе).

---

## Как пользоваться этим набором

1. Прочитай **[00-environment.md](./00-environment.md)** — там запуск игры, инжекция ввода,
   способы верификации и полный список маркеров консоли, на которые опираются тесты.
2. Исполняй тест-кейсы по файлам-граням (ниже). Каждый TC самодостаточен: предусловия, шаги,
   ожидаемый результат, способ проверки.
3. Каждый TC помечен **Покрытие** (F-ID) и **Тип** (`логика` / `ввод` / `визуал` / `модель`).
4. Результат веди по форме: `TC-ID · PASS/FAIL/BLOCKED · доказательство (log-цитата/скриншот)`.

## Базовая цепочка setup'а (создание фотографии через камеру)

Все JSON-сценарии используют общий префикс: **создание фотографии** из камеры в слоте 0.
Это единственный способ получить фото (камера не расходуется при активации, но уничтожается
при срабатывании — заменяется фотографией).

Цепочка (входит в setup каждого JSON):
```
wait_frames 90 (инициализация мира)
→ mouse_motion dx:0 dy:-20 (опустить камеру — гарантия взгляда в коридор)
→ I → 1 → 1 → I (активация фотоаппарата в слоте 0)
→ ЛКМ (открыть видоискатель + начать отсчёт 3→2→1)
→ wait_frames 150 (2.5 с — завершение отсчёта ~2.0 с + запас)
→ фотография в слоте 0, слот забронирован
```

После этого setup'а конкретный TC активирует фотографию (`I → 1 → 1 → I`) и выполняет
свои действия (ход вперёд, деактивацию, и т.д.).
