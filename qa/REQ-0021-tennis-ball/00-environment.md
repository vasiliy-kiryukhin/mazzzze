# 00 — Окружение, запуск, ввод, верификация

> Общая преамбула для всех тест-кейсов REQ-0021. Прочитай перед первым прогоном.

## Системные предусловия

- ОС Linux/X11 (игра использует захват мыши; на Wayland инжекция ввода идёт через `ydotool`).
- Сборка C#: `dotnet build` (обязательно после любого изменения `.cs`).
- Ассеты импортированы: `"$GODOT" --headless --import` (обязательно после свежего клона —
  иначе `base_ball.glb` и модели монстров невидимы; см. AGENTS.md).
- `DISPLAY=:0` доступен (GUI-окно). Без GUI бо́льшая часть THROW/VIS/MODEL-тестов невыполнима.

### Путь к движку (абсолютный, из репозитория)

```bash
GODOT="$PWD/.bin/Godot_v4.7-stable_mono_linux_x86_64/Godot_v4.7-stable_mono_linux.x86_64"
```

## Стартовая конфигурация игры (важно дляsetup'ов)

- **Мяч засевается в слот 1** (`InventoryHud._Ready`): ряд 1, колонка 2 → активация `I` → `1` → `2`.
  В слоте 0 лежит фотоаппарат. Лог старта: `[Inventory] Seeded 2/12 items`.
- **Спавнится 3 ифрита** (`MonsterSpawner`, кольцо 4–11 клеток от старта, позиции **случайны**).
  Лог: `[Monster] Spawn 'ifrit' cell=(x,y) seg=[..]`. Позиции монстров НЕ фиксированы —
  во всех F-49-тестах **сначала найди монстра** (миникарта / лог клетки), потом выстраивай сценарий.
- Игрок стартует в клетке входа (`PlayerStartCell`), смотрит в коридор. Мышь захвачена всегда.

## Запуск тестовой сессии

Игру нужно запустить с захватом stdout в лог (все верификации по консольным маркерам):

```bash
# 1. Сборка
dotnet build

# 2. (если нужен свежий импорт) "$GODOT" --headless --import

# 3. Запуск окна с логом
DISPLAY=:0 "$GODOT" --path . > /tmp/ball_test.log 2>&1 &
GODOT_PID=$!

# дать окну раскрыться
sleep 6

# 4. Активировать окно Godot для инжекции клавиш
xdotool search --sync --name "Maze" windowactivate %@   # подбери заголовок через xdotool search --name
```

По окончании сессии: `kill $GODOT_PID`. Лог живёт в `/tmp/ball_test.log`.

## Инжекция ввода

Мышь в игре захвачена (`MouseMode = Captured`). Используй `xdotool` (X11) или `ydotool` (Wayland).

| Действие в игре | Команда xdotool |
|-----------------|-----------------|
| Открыть/закрыть инвентарь (I) | `xdotool key i` |
| Выбрать ряд 1 / колонку 2 | `xdotool key 1` ; `xdotool key 2` |
| Движение (W/A/S/D) | `xdotool keydown w` … `xdotool keyup w` |
| Обзор мышью (yaw/pitch) | `xdotool mousemove -- 50 0` (относительные движения) |
| Зажать ЛКМ (заряд) | `xdotool mousedown 1` |
| Отпустить ЛКМ (бросок) | `xdotool mouseup 1` |
| Короткий тап ЛКМ | `xdotool click 1` |
| RMB (отмена) | `xdotool click 3` |
| Выход | `xdotool key ctrl+q` (или `kill $GODOT_PID`) |

**Время заряда.** `MaxChargeTime = 1.0 с` (плато). Полный заряд = держать ЛКМ ~1.1–1.3 с.
Минимальный бросок = тап < 0.1 с.

**Тайминги пиши через `sleep`:** `xdotool mousedown 1 && sleep 1.2 && xdotool mouseup 1`.

> Если `xdotool key` не доходит — проверь фокус окна (`xdotool getactivewindow`).
> Захват мыши у Godot'а не мешает `mousemove` — движок получает относительные события.

## Способы верификации

### 1. Консольные маркеры (основной способ для логики)

Игра пишет в stdout узнаваемые строки. Проверяй через `grep` по `/tmp/ball_test.log`:

| Маркер | Что означает |
|--------|--------------|
| `[Inventory] Seeded 2/12 items` | Мяч и фотоаппарат засеяны (слот 0, 1) |
| `[Inventory] Activate 'tennis_ball' → hand (slot 1 reserved)` | Мяч активирован в руку |
| `[Inventory] Pickup 'tennis_ball' → slot N` | Мяч вернулся в инвентарь (авто-подбор, REQ-0016) |
| `[Inventory] Throw 'tennis_ball' force=X.X (aware monsters=N)` | Бросок выпущен; N монстров видели бросок |
| `[Throw] launch force=X.X dir=(..) aware=N` | Снаряд создан, направление и сила |
| `[Throw] land → WorldItem at (x, z)` | Снаряд остановился → стал лежащим предметом |
| `[Throw] HIT 'ifrit' (aware) → stun` | Попадание в монстра, видевшего бросок → стан |
| `[Throw] HIT 'ifrit' (unaware) → no stun` | Попадание в монстра, НЕ видевшего бросок (без стана) |
| `[Monster] 'ifrit' stunned 2.5s` | Монстр в стане (BeHit), 2.5 с |
| `[Monster] 'ifrit' → Distract (item 'tennis_ball')` | Монстр отвлёкся на лежащий мяч |
| `[Monster] 'ifrit' → Threat (chase)` | Монстр увидел игрока (контроль для distract/throw-seen) |
| `[Monster] Spawn 'ifrit' cell=(x,y) seg=[..]` | Координаты монстра для построения сценария |

Пример проверки:

```bash
grep -E "\[Throw\] land|\[Throw\] HIT" /tmp/ball_test.log | tail -5
```

### 2. Скриншоты (визуал / модель / бесшовные переходы)

```bash
import -window root /tmp/shot_01.png     # ImageMagick (или: scrot /tmp/shot_01.png)
```

Сравнивай «до/после»: мяч в руке vs мяч в полёте vs мяч на полу (размер не должен меняться —
это регрессия «BallSize»). Для покадровых проверок (отскок, качение) делай серию с малым
интервалом: `for i in 1 2 3 4 5; do import -window root /tmp/seq_$i.png; sleep 0.15; done`.

### 3. Временные отладочные принты (последнее средство)

Если маркеров не хватает — поставь **временный** `GD.Print` в нужный метод
(`ThrowProjectile._PhysicsProcess`, `Monster.UpdateAnim`), прогонай, **удали** после.
См. AGENTS.md «Verification». Не оставляй отладочный код в коммите.

## Соглашения о сценариях (монстры случайны)

Позиции монстров рандомны каждый прогон. Поэтому F-49-тесты строятся по схеме:

1. На старте прочитай лог `[Monster] Spawn 'ifrit' cell=(x,y)` (все 3 монстра).
2. По миникарте найди монстра, подходящего под сценарий (в прямой видимости / за стеной).
3. Займи позицию игроком (повернись камерой, подойди/отойди), контролируя «видит/не видит»
   через `[Monster] 'ifrit' → Threat (chase)` (появился = видит; нет = не видит).
4. Выполни бросок, проверь ожидаемый маркер.

Если сценарий не получается из текущей генерации (например, нет монстра за стеной рядом) —
сделай `kill $GODOT_PID` и перезапусти (новый сид → новые позиции). Это **не FAIL теста**, а
проблема окружения — отметь `BLOCKED → restart` и повтори.
